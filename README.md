# 魔法玻璃 · v9：擦玻璃 + 混色画画 + 投水球（家用试玩版）

**在线试玩：<https://yizhuang90.github.io/magic-glass/>**（电脑 Chrome / Edge、iPad Safari 均可）

孩子站在摄像头前隔空挥手，屏幕上有一只（或两只）**跟着真手动的卡通虚拟手**：

- **🧽 擦玻璃**：玻璃被雾气或泥巴盖住，用虚拟手把玻璃擦开，露出后面的大字母、英文单词、中文和图画；擦开约 70% 就庆祝并朗读，然后换下一张。擦完后可以点 **“🎨 去给它涂颜色”**，把这张卡的线稿带进画画模式当涂色底稿。
- **🎈 投水球**：后院草坪上，软萌小怪兽从篱笆和灌木丛后面冒出来。在篮子里握拳拿一个水球，朝怪兽挥手、张开手扔出去，打中了怪兽会换成哭脸、掉眼泪、“哇——哇”地哭一下，然后躲回去（v9：怪兽是 AI 画的贴图，8 只、都没有角和翅膀：粉色团子、薄荷毛球、天蓝小熊耳麻薯、蜜桃蛋、紫色小豆、柠檬小芽、珊瑚红、青柠绿；每次随机冒出来，同屏不重样）。先自由扔几次熟悉手感，然后语音出题：“打 3 号”“打字母 B”“打‘大’字”。
- **🎨 混色画画**：从左右两边的颜料罐里“抓”颜色，在画纸上涂；两种颜色涂在一起会像真颜料一样混出新颜色（红 + 黄 = 橙），每发现一种新颜色就用中英文念出来，并记在右下角的“我发现的颜色”卡上。

其他特点：

- 纯静态网页，无需构建，可直接放到 GitHub Pages / Netlify 等静态托管。
- 手部识别：MediaPipe Tasks Vision HandLandmarker（从 jsDelivr CDN 和 Google 存储加载，**首次打开需要联网**），优先 GPU，失败自动改用 CPU。
- 🔒 隐私：摄像头画面只在本机浏览器内逐帧识别手的位置，**不录像、不截图、不上传**。上传的“孩子的画”只保存在本机浏览器（localStorage）里；“保存”的画作只下载到本机。

## 怎么玩

1. 打开网页，点 **“开始”**，浏览器询问摄像头时点 **“允许”**。没有摄像头就点 **“用鼠标 / 触屏玩”**。
2. **首页**有三张大卡片：🧽 擦玻璃、🎨 混色画画、🎈 投水球。把虚拟手停在卡片上约 1 秒（会出现进度），或直接用鼠标点击。
3. 每个游戏左上角都有 **🏠 首页** 按钮，手停在上面约 1.5 秒返回（键盘 H 也可以）。

### 投水球规则

| 动作 | 怎么做 |
|---|---|
| 拿水球 | 把手移到屏幕下方中间的**篮子**上，**握拳**（约 0.1 秒），水球就到手里了，会在手里晃。在别处握拳没用，每次都要回篮子拿；水球无限多 |
| 扔 | 朝怪兽**挥手**，同时**张开手**。方向和力度来自张手前一小段（平滑后的）手的轨迹，带一点向上的弧线。在篮子里原地张开手 = 放回去 |
| 瞄准辅助 | 很宽松：扔出方向 ±32° 以内、或落点附近的怪兽会被自动“吸”过去；手直接在怪兽身上张开也算打中 |
| 鼠标 / 触屏 | 在篮子上按下，拖动后松开，按拖动的速度扔出 |
| 打中 | 换哭脸 + 抖一抖 + 抽泣，脸上掉眼泪，配一声短短的委屈哭声（约 0.9 秒），哭约 1.5 秒后缩回去。打中时的水花从身体边缘往外炸开、很快散掉，星星出现在头顶，哭脸马上就看得见。打错（目标模式里打了别的）不会哭，而是笑着跳开 |
| 自由模式 | 怪兽肚皮上只有一个小爱心，打中哪只都算，每打中一次加一颗星 ⭐（没有时间限制） |
| 目标模式 | 自由模式打中 5 次（可调）后语音说“现在试试打 3 号！”。屏幕上 3–4 只怪兽身上有大字，顶部题目牌显示要打的字。打对：彩虹水花 + 表扬 + 下一题（不会连续两次同一个）；打错：怪兽咯咯笑着跳开，不扣分；约 8 秒没打中会再说一遍（也可以把手停在“🔊 再听”上）。要打的那只一直留在画面里 |

家长设置 → “投水球”：怪兽身上的字（数字 1–10 / 大写字母 / 常见汉字 / 混合）、跳过自由练习、自由练习打中几次后出题。

**安全区**：篮子、怪兽、字、按钮全部放在离屏幕边约 4–5% 以内的区域；篮子在底部中间、离底边还有一段距离，篮子的感应区一直延伸到屏幕下沿，手放得再低（被安全区夹在屏幕底边）也能拿到水球，孩子不用把手伸出摄像头的识别范围。

### 虚拟手

- 虚拟手由 MediaPipe 识别出的 21 个手部关键点画成：半透明、带描边、圆润的卡通手，和孩子的手**镜像对应**（孩子举右手，屏幕右边的手动）。弯手指、握拳、张开都能看出来。两只手颜色不同（第一只黄色、第二只蓝色）。
- 擦玻璃时，**整只手就是抹布**（手心有一块小海绵），手掌和手指扫过的地方都会被擦开。
- 画画时，手心显示**当前选中的工具**（颜料球或橡皮擦），食指指尖有一个**笔尖光圈**：只伸食指时光圈变成实心、发光（正在画）；张开手或握拳时只是一个虚线圈（只移动、不画），让孩子知道笔在哪里。选了橡皮擦时，指尖显示粉色的擦除圈和小橡皮。
- 鼠标模式也显示虚拟手：**按住鼠标时握拳**（擦 / 涂），松开时张开（只移动）。
- 摄像头看到真手、而鼠标静止约 0.8 秒后，**鼠标的虚拟手会自动隐藏**（不再涂抹、擦拭或悬停触发按钮），直到鼠标真的再次移动（超过 2 像素的轻微抖动、程序合成的事件都不会唤回）。首页、擦玻璃、画画都一样。

### 混色画画规则

| 动作 | 怎么做 |
|---|---|
| 选颜色 | 把手移到左边（红、黄、蓝）或右边（白、黑）的颜料罐上，**握拳保持约 1 秒**，进度环走满就选中了，罐子外面出现手颜色的虚线框（鼠标：在罐上按住约 0.5 秒）。**握拳只用来选颜色，不会画** |
| 画画 | **只伸出食指**（中指、无名指、小指弯起来，大拇指随意），食指指尖就是画笔；鼠标按住拖动 |
| 不画 | **张开手**、握拳、或其他手势都不画，只是移动手；这样孩子可以放心把手移到别处 |
| 颜色保持 | 选中的颜色一直不变、不会用完，张开手、手离开画面再回来都还在，直到再去抓下一个颜色。两只手各自记住自己的颜色 |
| 橡皮擦 | 右边颜料罐下面的 **橡皮擦**（粉蓝色橡皮图标） 也是握拳 1 秒选中；之后只伸食指就会擦掉一个较大的圆形区域，露出白纸。再抓任意颜色就回到画笔 |
| 混色 | 在已经涂过颜色的地方涂另一种颜色，会在画纸上混合成新颜色（手上的颜色本身不变） |
| 提示 | 顶部右侧有提示条：✊ 选颜色 · ☝️ 画画 · ✋ 不画；进入画画时会朗读“握拳抓颜色，伸出食指画画”；还没选颜色就伸食指，会提示先抓颜色 |
| 按钮 | 顶部 **↩️ 撤销 / 🧽 清空 / 💾 保存**，手停在按钮上约 1 秒触发，鼠标直接点击；保存会下载 `魔法玻璃画画_日期_时间.png` 到“下载”文件夹 |

混色使用 [Mixbox](https://github.com/scrtwpns/mixbox)（基于颜料物理的减色混合模型），所以黄 + 蓝 = 绿，而不是 RGB 平均出来的灰绿色。

### 区分玩家（左右手）

- 摄像头画面里检测**人脸的位置框**（MediaPipe FaceDetector，约 10 次/秒），每只手分给离它最近、位置合理的那个人（手腕在脸的下方或两侧、离得不太远；举手过头也算），再用手部模型的左右手结果标出**左手 / 右手**。
- 颜色按“**几号玩家 + 左/右手**”记住：1 号的右手抓了黄色、左手抓了红色，2 号的右手抓了黑色……各不影响。手离开画面再回来，也会拿回自己的颜色。
- 虚拟手的颜色跟着玩家走（1 号黄、2 号蓝、3 号粉、4 号绿），手腕旁有**号码 + 左/右**的小标记；每个人脸的位置还有一个淡色号码圆点。
- 人脸短暂看不到（转头、低头）有 2 秒宽限，号码不变；看不到人脸时自动退回“按手区分”，手上的颜色跟着手走。
- **隐私**：只用人脸的位置框来判断“这只手是谁的”，**不做人脸识别、不提取特征、不保存也不上传任何画面**；号码只在本次运行中有效（人离开超过 2 秒再回来会拿到新号码）。可以在设置里关闭“区分玩家”，关闭后不运行人脸模型。

### 家长设置

长按右上角小齿轮 **1 秒**（孩子不易误触），或按键盘 **P**。可以设置：

- **摆放方式**：🖥️ **屏幕模式**（默认，摄像头在屏幕上方对着孩子，孩子隔空挥手）/ 📽️ **投影模式**（四角标定对齐投影画面）。
- 屏幕模式下：**安全区边距**（默认 15%）和**下边多留**（默认 +10%）：只把摄像头画面中间的一块映射到整个屏幕，安全区外的手停在屏幕边上。孩子够不到屏幕边就把边距调大；按 **V** 打开小预览能看到黄框（框外变暗）。还有**虚拟手大小**。
- **区分玩家**（默认开）：每个人的左手、右手各记各的颜色（见下面“区分玩家”）。**最多识别几只手**：4 只（两个人，默认）或 2 只（一个人，更省）。
- 雾气 / 泥巴、过关比例、慢慢重新起雾、朗读语言（中文 / 英文 / 双语）、音量、选择摄像头、上传孩子的画、下一张、全屏、性能浮层。
- **画质 / 流畅度**：🚀 流畅（默认）/ ⚖️ 自动 / ✨ 高画质，见下面“性能说明”。
- **高级 → 内部渲染分辨率（最长边）**：只在“高画质”时使用（默认 1440）。

| 快捷键 | 作用 |
|---|---|
| P / S | 打开 / 关闭家长设置 |
| H | 回首页 |
| N | 下一张（擦玻璃） |
| V | 摄像头小预览（调试用） |
| F | 性能浮层（渲染 fps、手 / 人脸识别 fps 和每次耗时、玩家数、内部分辨率、MediaPipe GPU/CPU） |
| Esc | 关闭设置 / 退出标定 |

全屏请用设置里的“全屏”按钮（或浏览器自己的 F11）。

## 本地运行

摄像头只允许在 **https** 或 **localhost** 下使用，直接双击 `index.html`（file://）打不开摄像头。

```bash
cd magic-glass
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

Mac 和 Windows 上用 **Chrome 或 Edge** 最稳定；Safari 也能运行但朗读声音和性能可能不同。

## 性能说明（v7：流畅优先）

- **识别放在单独的线程（Web Worker）**：MediaPipe 手部 + 人脸识别不再占用画画面的主线程，识别再慢，画面和虚拟手也保持流畅（实测：同样很慢的识别下，渲染从约 2 fps 提升到 60 fps）。浏览器不支持（Worker 里没有 OffscreenCanvas WebGL2，如旧版 Safari）时自动退回主线程识别。
- **GPU / CPU 自动选择**：识别线程先用 GPU；如果 GPU 明显很慢（例如 Chrome 跑在没有硬件加速的虚拟显卡上），会自动试 CPU，留下更快的那个，性能浮层会显示“GPU 太慢…已改用 CPU”。
- 摄像头请求 640×480；送进模型的画面最长边不超过 640（摄像头给了更大的画面会先缩小）。手部识别最多约 30 fps；人脸框（区分玩家）约 5 fps，画面里少于两只手时约 2 fps。
- **家长设置 → 画质 / 流畅度**：
  - 🚀 **流畅（默认）**：内部画布最长边 1024 px，关掉阴影模糊、粒子更少；仍然卡（约 2 秒平均低于 45 fps）会再自动降到 860 → 720。
  - ⚖️ **自动**：从 1280 px 开始，卡了自动降（最低 860）。
  - ✨ **高画质**：用“高级 → 内部渲染分辨率”（默认 1440），不自动降。
  - 内部画布的像素数和屏幕大小、Windows 缩放（devicePixelRatio）无关，3072×1920 的屏幕也只画这么多像素，再用 CSS 拉伸到全屏。自动降档在首页 / 投水球里立即生效；擦玻璃 / 画画里等下一次换模式才生效，不会清掉画到一半的画。
- 雾气模糊每张卡只生成一次并缓存；每帧只更新被擦到的那一小块区域。画画的混色只在笔刷下面的小块区域计算；背景、颜料罐、草地篱笆都缓存成图片。
- 按 **F** 打开性能浮层：渲染 fps、手 / 人脸识别 fps 和耗时、**识别线程（Worker / 主线程）**、**MediaPipe GPU / CPU**、画质档位和内部分辨率、屏幕物理分辨率和 dpr、**摄像头实际分辨率**。觉得卡的时候，把这几行拍给我看最有用。
- **如果渲染 fps 明显偏低**：在 Chrome 地址栏打开 `chrome://gpu`，看 “Canvas” 和 “WebGL” 是否为 “Hardware accelerated”。装了**向日葵**等远程控制软件的“虚拟显示器驱动”时，Chrome 可能跑在虚拟显卡上而没有硬件加速：可以在 Windows“设置 → 系统 → 屏幕 → 显示卡”里给 Chrome 选“高性能”（Intel Arc），确认 Chrome 窗口在真实显示器上，必要时在设备管理器里暂时禁用虚拟显示器，再重启 Chrome；Chrome 设置里的“使用图形加速功能（如果可用）”也要开着。
- 调试：网址后加 `?worker=0` 强制在主线程识别（对比用）。

## 部署到网上（https 网址）

整个目录就是网站，无需构建。`./build.sh` 会生成只含网站文件的 `dist/`。

**GitHub Pages（推荐，长期免费）**
1. 在 github.com 新建仓库（如 `magic-glass`，公开仓库才能免费用 Pages）。
2. 仓库页面 “Add file → Upload files”，把 `dist/` 里的全部文件（`index.html`、`css/`、`js/`、`.nojekyll`）拖进去，提交。更新时同样上传覆盖即可。
3. Settings → Pages → Source 选 “Deploy from a branch”，分支 `main`、目录 `/ (root)`，保存。
4. 约 1 分钟后打开 `https://<你的用户名>.github.io/magic-glass/`。

**Netlify Drop**：打开 https://app.netlify.com/drop ，把 `dist` 文件夹拖进去即可得到 `xxx.netlify.app` 网址。不登录时网址带临时密码、1 小时内需登录认领，否则会被删除；登录后长期有效。

## iPad 上玩（Safari）

1. 用 Safari 打开 <https://yizhuang90.github.io/magic-glass/>，点 **“开始”**，允许使用摄像头（用的是前置摄像头）。点一下屏幕同时会解锁声音和朗读。
2. 建议 Safari 分享按钮 → **“添加到主屏幕”**，从主屏幕图标打开就是全屏、没有地址栏（iPad Safari 网页不能真正全屏）。
3. **横放**，前置摄像头那一边朝上更好；旧款 iPad 的前置摄像头在竖放时的顶部，横放时在侧边，孩子会显得偏在画面一侧，可以把“安全区边距”调大一点。iPad 立在桌上或支架上，孩子站在 1–1.5 m 外。
4. 没有摄像头时也可以**手指直接在屏幕上玩**：在颜料罐上按住约 0.5 秒抓颜色，拖动画画；摄像头看到真手时触摸手会隐藏，规则和鼠标一样。
5. 声音：iPad 侧边静音开关 / 静音模式打开时可能没有音效；朗读用 iPad 自带语音。
6. 卡顿时：设置里把手的数量改成 2，或关掉“区分玩家”。首次打开要下载约 15–20 MB 模型。

页面已禁止双指缩放、双击放大、页面滚动和下拉刷新（设置面板内部仍可滚动）。

## 家里摆放

**屏幕模式（默认，普通电脑 / 电视）**
- 摄像头放在屏幕上方中央，对着孩子；孩子站在离屏幕 1–2 m 处，举手时双手都在摄像头画面里（按 V 看预览）。
- 默认安全区：摄像头画面左右上各留 15%，下边留 25%（孩子的手放低时常常出画面）。孩子够不到屏幕边缘时，在设置里把“安全区边距”调大；手放低够不到屏幕下沿就调大“下边多留”。贴着屏幕边的颜料罐和按钮，感应区一直延伸到屏幕边，手“顶”到边上就能碰到。

**投影模式（墙面或白板）**
- **投影面**：白墙或白板，画面宽 1.5–2 m，底边离地 40–60 cm。
- **投影距离** = 投射比 × 画面宽度。普通家用投影仪（投射比约 1.2–1.5）投 1.8 m 宽需离墙约 2.2–2.7 m；短焦机约 0.9 m。投影仪尽量放高或偏到一侧，减少孩子的影子。
- **摄像头**：放在画面下沿中央，高约 60–90 cm，朝向孩子、略微上仰。画面里不要有窗户、电视或投影画面。
- **标定**：✋ 手指指四角（家长依次用食指指向四个闪烁的星星，每个约 1.3 秒），或 🖱️ 在摄像头预览上拖动四个圆点框出可玩区域。结果保存在本机浏览器，“重置为全画面”可清除。

通用：开着室内灯，拉上孩子背后的窗帘（避免逆光）；线材固定好，孩子周围留出约 1.5 m × 1.5 m 空地。

## 代码结构


## 已知局限

- 区分玩家靠人脸位置：两个孩子靠得很近、手伸到对方面前时，手可能被分给另一个人（会尽量保持上一帧的归属）。孩子背对摄像头或戴面具时看不到人脸，会退回按手区分。
- 真手手势（握拳选颜色、只伸食指画画）目前只用模拟的关键点测试过，还没有用真孩子的手测。判断用的是手指相对长度（与手大小、远近、角度无关），阈值集中在 `js/input/gestures.js` 的 `POSE_T`，需要时可以微调。食指正对摄像头时画面里会变短，可能偶尔断笔，竖着朝上伸食指最稳。
- 投水球的“挥手 + 张开手”目前只用模拟的手测试过。摄像头里“朝屏幕推”的动作主要表现为手往上移，所以往上挥最准；张开手要被确认 2 帧（约 0.07 秒），出手速度取张手前约 0.3 秒内最快的一段。太灵 / 太迟钝时可以调 `js/game/throwLogic.js` 里的射程和瞄准辅助参数。
- 颜色命名是按“离哪个已知颜色最近”估的，奇怪的混色可能会被叫成不太准确的名字（如偏蓝的颜色叫“深蓝色”）。
- 首次打开需要联网加载 MediaPipe（约 15–20 MB，之后浏览器会缓存）。
- 朗读用系统自带语音；有的 Windows 电脑没有中文语音，需要在系统设置里添加“中文（简体）”语音包。
- 孩子离摄像头超过约 2.5 m 时手部识别会明显变差；背景里有家人走动可能被当成另一只手。
- Chrome 没有用上硬件加速时（见“性能说明”）会明显卡顿。
- emoji 图画的样式取决于系统字体（Mac 和 Windows 的 emoji 长得不一样）。
